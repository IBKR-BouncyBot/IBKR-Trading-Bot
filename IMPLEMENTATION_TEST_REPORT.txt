BouncyBot v5.7.0 - Implementation and verification report
Date: 2026-10-08
Scope: let an already partially filled marketable BUY continue filling
Baseline: exact released 5.6.2 source, git tag v5.6.2 (67b4023)
Baseline source ZIP SHA256:

REQUESTED POLICY CHANGE

The user requested that partially filled market orders remain working so the
original order can fill completely, without unrelated application changes.
Version 5.7.0 removes automatic BUY-remainder cancellation caused by the fixed
three-second partial-fill timeout or changing post-fill market/session checks.
This covers a directly submitted MKT BUY and a native TRAIL BUY that has already
triggered and received a positive fill. No second or replacement BUY is created.

The bot continues supervising the original broker order in Stage 2, recording
additional executions and commissions. It waits for broker terminal status before
settling the BUY and proceeding with the acquired quantity. The change allows the
broker to continue filling; it cannot guarantee full execution or execution price.

PRESERVED BEHAVIOR AND EXCEPTIONS

- Pre-submission data, identity, quantity, RTH, spread, margin and risk checks.
- Native order types, trigger terms, routing, outsideRth and time in force.
- Explicit operator Stop/cancel/market-close requests and cancellation races.
- The separate configured pre-close BUY cancellation, including a partial BUY.
- Cancellation of a replacement order when late historical SELL evidence exposes
  an existing position/exposure conflict.
- Broker terminal cancellation or rejection: settle only the proven acquired
  quantity; do not silently submit another BUY to obtain the original target.
- Existing Stage-3/SELL/protective-order behavior, fill deduplication, fees,
  reconnect/recovery, auto-repeat rules and database compatibility.

No new setting, schema migration, dependency, worker, polling interval, backup
policy or GUI layout is introduced. Runtime behavior changes are confined to
app/controller.py. app/gui.py changes only three release-version strings.
app/strategy.py changes only its obsolete partial-fill policy docstring; its
executable AST is unchanged. The broker adapter, models, storage, order-edit
policy, main.py, requirements and all 27 image assets remain unchanged.

The implementation removes the retired partial-fill timer/safety/cancel helpers
and updates BUY_PARTIAL_FILL audit text to describe waiting for the original
order or an already-requested cancellation. It retains existing audit cadence.
Documentation and release metadata are synchronized. The prior 5.6.2 release
note and byte-identical implementation report are archived under docs/legacy.

OBSERVED AMD EVIDENCE

The supplied AMD cycle-33 audit contains an original BUY of 15 shares, one actual
execution of 10 shares at USD 655.72 and USD 0.382287 commission. The prior policy
requested cancellation of the five-share remainder after 0.253099 seconds because
independent bid/ask freshness failed. IBKR confirmed cancellation. The bot then
settled Stage 3 with 10 shares; a later broker position probe also reported 10.

The supplied BUY_FILL capture contains 15,042 rows over the 30-minute window.
Its saved fill snapshot has bid USD 655.42 with recorded update age 9.4356 seconds,
ask USD 655.73 and Last USD 655.60 with age 0.1918 seconds. The configured maximum
bid/ask age was seven seconds. Live data, upstream connectivity and RTH were
confirmed. The captured spread was approximately 0.0473%, below its 0.5% limit.
The subsequent bid-price update is recorded after cancellation was requested.

The evidence explains the old cancellation and supports replaying the condition.
It does not establish that the standing exchange bid was invalid, that all five
remaining shares would have filled, or the counterfactual execution price.
No unobserved completion is described as an actual historical fill.

AUDIT-DERIVED REGRESSIONS AND REVIEW

A compact sanitized fixture preserves the observed order quantities, prices,
commission, status shapes and independent quote-field update evidence from both
supplied archives. Account, cycle, order and execution identifiers are replaced.
Archive hashes and selected source-record provenance identify the input evidence
without shipping the original database, full capture or raw private identifiers.

Tests replay the original partial BUY with the captured stale-bid/fresh-ask
snapshot through the real controller and SQLite with audited order-state and
callback inputs at a deterministic broker boundary. They verify that
the original order remains working beyond the retired timeout, no cancellation
or extra BUY is sent, no early SELL is placed, and quantity/stage/fees remain
correct. Additional explicitly controlled continuations model later fills,
terminal broker cancellation, repeated evidence and recovery; they are test
variants, not claims about events absent from the audit.

Tests that previously required automatic timeout or market-condition cancellation
are updated for the requested new contract. Controls retain pre-entry blocking,
configured pre-close cancellation, explicit cancellation and late-fill accounting.
Selected regressions are run unchanged against 5.6.2 and 5.7.0 to demonstrate the
behavior difference. Independent review checks preserved cancellation paths and
that only the intended controller handler changes among retained functions.

EXECUTED VERIFICATION

- Standard unittest discovery: 1,115 tests run, zero failures/errors, seven skip
  records for unavailable PowerShell or native Qt checks. This includes all 20
  new AMD replay tests. Class-level skip records do not imply a measured count
  of native test methods exercised.
- Complete limited function-test fallback: 1,493 parameterized cases passed,
  zero failures or module errors. This is not an actual pytest run. Its six
  runner self-tests also passed. The 37 updated partial-policy cases are included.
- Official mutation smoke: all 17 safety mutants killed.
- Official CSV simulation gate: 58 scenarios passed across 54 price-path files.
- Red/green check: three identical AMD regressions fail by assertion on 5.6.2
  and pass on 5.7.0, with no execution errors. This verifies the captured quote
  condition, the removed timeout and the controlled direct-market-order case.
- Independent review: no blocking finding; 156 focused checks passed, comprising
  73 existing manual-close/recovery/protection tests, 26 entry-guard tests,
  37 partial-policy cases and 20 AMD replay tests. These overlap the full suites
  and are not added to their totals.
- Scope review: 278 retained controller functions unchanged by AST comparison;
  only the retained BUY-fill handler changes. Three obsolete helpers are removed.
  All 223 Python files parse; 559 local documentation file links resolve.
- Source inventories confirm no executable/test changes during verification.
  A full run first found seven release-note filename assertion failures. Eleven
  expected filename strings in those seven tests were corrected, and the entire
  limited function suite was rerun successfully. Hash comparison proves these
  were the only intervening execution-source changes; earlier passing unittest,
  mutation and simulation results remain applicable. A README current-release
  link and this report were finalized separately as documentation-only edits.

Runs use ResourceWarning-as-error where supported by the verification runners.
Audit replays use disposable databases and deterministic broker boundaries; no
test connected to the user's broker or submitted an order. Logs, source hashes,
required-gate failures and independent review are included in Release_files.

PLATFORM LIMITATIONS

Host: Linux CPython 3.12.14. The supported target remains standard GIL-enabled
CPython 3.14.x on Windows. The current tool inventory remains unchanged from the
same-day 5.6.2 check, whose bounded Python 3.14 and unchanged-dependency installation
attempts failed HTTP403. Those earlier attempt logs are labelled as prior evidence;
they are not presented as newly successful installation or a new runtime test.

Actual pytest/coverage, Ruff, Pyright, native PySide6, ib_async, PyInstaller and
PowerShell are unavailable on this host. The official require-tools quality and
runtime gates do not pass here. Offline fallback runs are not pytest, measured
coverage, native Windows/Qt tests, a Windows build or a paper/live broker session.
No prebuilt Windows executable is supplied. Supported-platform and paper-account
acceptance checks remain outstanding; the current test plan documents them.

UPGRADE AND EXISTING PARTIAL CYCLES

Keep each instance's existing database, configuration, client ID, captures and
backups. Use the full Source ZIP, or apply Release_files to the exact 5.6.2 source
baseline. Run the documented tests/build on Windows CPython 3.14 before deploying
a rebuilt executable. Copying .py files beside an old executable does not update
that executable. Restart, connect and explicitly resume the stored strategy.

The new policy applies to a BUY that is still working. It does not reopen an
already-cancelled order, change its executions, or buy missing shares for a cycle
already settled to Stage 3. In particular, the supplied AMD cycle's 10-share
holding is not automatically increased to 15 by this release.

Packaging validates the exact baseline and checks that both the patch and manual
file overlay reconstruct every file of the complete Source ZIP byte-for-byte.
Archives include the targeted code, tests, documentation and verification evidence;
they exclude supplied databases and full private audit/market-capture bundles.
