SCOPE AND COMPATIBILITY
Only app/gui.py changes among runtime application sources. All other app/*.py
files and main.py are byte-identical to that baseline. There is no strategy,
broker, order, controller, storage, watchdog, ATR or database-schema change.
The last-five-minutes/session-close/orderly-app-close ATR saving policy is
retained. Keep the existing v4.0.0 database. Dependencies and CSV schemas are
unchanged. Version, Windows build metadata, tests and documentation are updated.
The previous v4.0.0 release note and corrected report are in docs/legacy/.

IMPLEMENTED REQUESTS
1. Trading status pill retains its existing status and color and adds a
   right-aligned current display price / minimum-profit trigger. Unavailable
   data shows dashes. Tooltips retain four-decimal detail and explain that the
   displayed pair is not proof of fresh executable quotes or SELL eligibility.
2. Position adds cost of the remaining app-owned shares, not account-wide
   holdings or mark-to-market value. Mirrored protective/final SELL quantities
   are not subtracted twice. No holdings are adopted or sized by this display.
3. Price monitor contains five aligned cards: Selected price, Source, Data mode
   with actual update age, Bid / Ask / Spread, and RTH status with UTC/system
   time. RTH/time spans two cells in the lower row. Freshness and quote checks
   themselves are unchanged. Raw API fields remain independently expandable.
4. The redundant Stage metric is removed from Market and strategy state only.
5. Current stage and Why not moving? are behind Show/Hide stage details. The
   panels still update while collapsed; the top Stage pill and stage ribbon
   remain. The toggle is not a controller or trading command.
6. The explanatory text beside Show raw API fields is removed.
7. Total BUY cost is placed between Buy filled qty and Sell filled qty.
8. OrderRef uses a read-only, wrap-anywhere text field. Copying preserves the
   full exact identifier. Very long content scrolls within the field rather
   than clipping or expanding the complete order column. Unchanged snapshots
   do not reset its selection.
9. Simple hides the Live Strategy Recovery / audit log panel. Advanced/Debug,
   audit recording and the separate Reconciliation tab remain available.
10. Completed trade summary has 12 cards in three columns and four rows. The
    added Average net P/L equals existing summary net P/L / completed cycles;
    it includes losing cycles and recorded costs and is unavailable for zero
    completed cycles. Existing summary scope is retained.
11. History adds Invested after Budget with raw numeric sorting. The amount is
    calculated from actual BUY fills and recorded BUY commission, not Budget.
    Existing row identity, filters and audit opening remain unchanged. The
    GUI-only derived column does not modify history rows or CSV export schema.
12. History no longer grows its minimum height with row count. It has a bounded
    viewport, vertical row scrolling, and a reserved horizontal scrollbar at
    the visible bottom. Row-count-driven height fitting was the problematic
    layout policy; tests cover zero, one, 19 and 500 rows and later clearing.
13. Hovering either audit Timeline plot shows a shared time guide in both. The
    other plot uses its nearest visible real record on its own price scale,
    with actual record time separate from cursor time. Empty counterparts get
    a time guide only. Moving outside/away clears the guides. Offscreen records
    cannot replace the linked guide's visible record tooltip.
14. Timeline transition/risk tables have equal 210-pixel heights with aligned
    upper/lower edges, independent scrolling, retained 3:2 widths and stretching
    Message columns.
15. Decision events fills its available lazy-loaded tab in both dimensions and
    stretches Message. Orders and Executions retain compact top-aligned tables.

COST DEFINITIONS
Total BUY cost and history Invested:
  actual buy_filled_qty * avg_buy_price + recorded buy_commission
Top Position cost:
  Total BUY cost * app-owned unsold quantity / actual BUY-filled quantity
Signed recorded fee rebates are retained. Missing/invalid fill facts are not
replaced by a budget or stale market price. An unfilled BUY has zero filled
cost; a fully exited position has zero remaining cost, but history retains
its full entry cost. Late commission updates can change the displayed amount.
These metrics are not tax-lot accounting, new order-sizing inputs, or broker
account-wide valuations. Existing USD/EUR database display currency is used.
