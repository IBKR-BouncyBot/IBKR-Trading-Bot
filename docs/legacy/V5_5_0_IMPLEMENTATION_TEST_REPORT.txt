CHANGES

1. Connection reports the local API and upstream broker links independently
   of the awaiting-fresh-data flag. Two confirmed connections display Connected.
   Disconnected, Gateway only, Reconciling and Checking link remain distinct.
   A confirmed link's tooltip no longer reuses an old message claiming that
   fresh market data is currently arriving.

2. Data presents known old prices consistently as, for example, Live / Stale
   6.3h, whether their event state is stale or invalidated. The measured age,
   actual receipt timestamp, pending-update flag and invalidation reason remain
   in its tooltip. Unknown data, recent invalidation, missing event tracking and
   upstream loss remain separate states. No invalidated quote becomes green.

3. Trading displays BUY blocked: RTH closed or SELL blocked: RTH closed only
   for an ordinary waiting stage whose blockers consist solely of rth_closed,
   stale_data and/or fresh_market_data_pending. All original blocker details
   remain in the tooltip. Disconnection, recovery/startup requirements, active
   storage faults, working-order stages and other blocker codes retain the
   controller's headline. Only display text changes; blocker lists are not edited.

4. The Price data monitor labels actual API event receipt time Last market
   update and separately labels cached snapshot check age. It never substitutes
   snapshot.timestamp or other cached-read times for missing event receipt time.
   Existing timestamp aliases remain supported. The timestamp is API receipt
   time, not an assertion about exchange execution time or each quote field.
   Old visible prices say Cached price - market data stale; recently invalidated
   visible prices say Cached price - awaiting a new market update. The legacy
   price-feed summary follows the same timestamp/status rules and uses the
   existing warning style for cached data.

5. Runtime/build/GUI version strings and current documentation identify 5.5.0.
   The previous 5.4.0 release note is archived with repaired links, and its
   implementation report is archived byte-for-byte. Existing branding, images
   and GUI layout are retained.

RUNTIME SCOPE AND REVIEW

Only app/gui.py changes among application modules. Every other app module,
main.py and requirements.txt was compared byte-for-byte with the corrected
5.4.0 baseline. The build script, runtime-check script and pyproject.toml differ
only in release-version strings. All 27 tracked Images/ files are unchanged.

No adapter, controller, strategy, order handling, persistence, subscription,
2104 handling, RTH/ATR check, freshness guard or timer interval changes are
included. The display helpers do not call the broker or database and do not
modify incoming snapshots. Existing standard GIL-enabled CPython 3.14.x
requirements are retained.

Independent review found one display issue in the first implementation: when
no cycle was active, the monitor defaulted to 3 seconds although the configured
strategy freshness limit could differ. MainWindow now supplies the current
strategy limit to both monitor paths, matching the ribbon/controller. The
optional PricePanel keyword preserves its existing two-argument callers.
A regression covers both no-cycle and differing persisted-cycle-limit cases.
No further concrete defect was found in the reviewed GUI changes.

The actual PURR and VWRL report snapshots were replayed through the GUI with
repository Qt stubs. Both show Connected and SELL blocked: RTH closed. Data
shows Live / Stale with their respective measured ages (6.5h and 6.3h in the
reports, which were captured at different times). Actual receipt timestamps
remain 11:18:52 UTC and 11:18:29 UTC. Cached prices remain visible, all blockers
remain in tooltips, and deep-copy comparisons show unchanged input snapshots.

VALIDATION LIMITS

Python 3.14, native PySide6/Qt, Windows/PowerShell, pytest/coverage, Ruff,
Pyright, ib_async and PyInstaller are unavailable on this host. The required
quality command was attempted and exited nonzero because Ruff/Pyright are
missing; it did not pass. This release has no native visual/build qualification
or fresh measured coverage. The Windows run_all_tests.bat and build remain
required target-environment checks. The manual GUI plan documents the relevant
status, tooltip, real-update and scaling checks.

The runtime safety modules are byte-identical to 5.4.0. Separate mutation and
CSV simulation launchers were not rerun for this GUI-only release; the complete
available unittest and function suites were run as described above. Prior
5.4.0 results remain explicitly historical in the archived report.
