CHANGES

1. Incomplete recovery reads now defer while preserving the current stage.
   Authoritative open-order, execution and exact-position requests require a
   completed response and confirmed local/upstream connectivity before/after.
   A failed request cannot silently become an empty result or cached substitute.
   Request errors are enabled and timeouts bounded to at most ten seconds only
   around these recovery requests; prior adapter settings are restored afterward.
   Ordinary cached polling remains separate and retains its existing behavior.

2. Recovery callers retain the pending pause until reconciliation succeeds.
   Empty managed-account snapshots wait; a completed nonempty snapshot excluding
   the pinned account remains a real discrepancy. Definite contract mismatch,
   insufficient/invalid completed position evidence and missing expected orders
   retain fail-closed review. The existing ten-second local reconnect and
   two-second pending-recovery intervals remain unchanged. Identical incomplete
   requests are coalesced, and position acquisition precedes ledger writes so
   repeated position timeouts do not repeatedly rewrite cycles/executions.

3. Reconcile and resume can clear the two observed legacy waiting-stage holds
   after fresh evidence proves them resolved. It requires one unresolved cycle,
   matching hold/prior-stage audit evidence, pinned account and positive conId,
   fresh complete broker reads and sufficient exact position. Stage 1 must have
   no order/fill evidence. Stage 3 must have a settled exact BUY and matching
   execution ledger. Contradictory structured or archived ownership evidence,
   working orders, new/conflicting fills, pending exits and protection transitions
   cannot pass this narrow classifier. Current holdings alone cannot infer stage.
   No temporarily cleared cycle is persisted before validation finishes.
   Successful restoration records OUTAGE_HOLD_RECONCILED. Failed proof reports
   the current reason. A same-cycle operator request survives transient retries
   in memory, ending on completed assessment or explicit Disconnect; restarting
   does not confer permission to clear an old hold automatically.

4. Outage status uses amber Waiting/Reconnecting and paused Trading presentation.
   Explicit operator Disconnect is distinguished from an active automatic retry.
   Genuine manual review, storage faults and unrelated guard failures retain
   their fault presentation. Start does not falsely report successful resumption
   when recovery remains incomplete or requires review.

5. Read-only identity failures immediately before transmission are also checked.
   Proven-unsent ordinary orders and queued close/repeat workflows now wait
   for unavailable broker evidence; genuine identity discrepancies stay held. An order
   that may already have reached IBKR remains SUBMISSION_UNKNOWN and is never
   blindly retried. Missing required protection remains a real exposure concern.
   A preflight-interrupted protective cancellation retains the working order.
   A repeated outage preserves queued close intent; actual uncertain cancellation
   remains a hold. Late legacy account-evidence reads also require completion.

SCOPE AND REVIEW

Runtime changes are confined to app/controller.py, app/ib_adapter.py,
app/storage.py and app/gui.py. Storage adds a bounded read-only lookup for
reconciliation evidence, with no schema migration. The pure strategy engine,
models, sizing calculations, RTH/ATR thresholds, quote guard requirements,
backup policy, dependencies, main.py and all 27 Images files are unchanged.
Current release metadata, documentation and corresponding metadata tests are
updated. The 5.6.0 release note and byte-identical prior verification report are
preserved under docs/legacy.

Independent reviews reproduced both incident paths, checked adapter request
completion, and exercised legacy-hold restoration. Reviews found additional
mixed-identity evidence, negative conId, pending BUY cancellation, repeated
position-timeout write and manual-Disconnect display edges; these were corrected
with regressions. Legacy broker repr text is parsed as literal AST evidence,
never evaluated. No live broker connection, live order or cancellation occurs
in this work.

VALIDATION LIMITS

The available host is Linux with CPython 3.12.14 and SQLite 3.53.1. The supported
application runtime remains standard GIL-enabled CPython 3.14.x. Fresh bounded
attempts to install Python 3.14 and the exact project requirements returned
HTTP 403. Actual pytest, coverage, Ruff, Pyright, PySide6, ib_async, PyInstaller
and PowerShell are unavailable. The required runtime and quality gates therefore
DO NOT PASS on this host. Dependencies and requirements were not weakened.

Standard-library unittest execution and the explicitly limited function-test
fallback run real project test bodies with temporary databases and deterministic
broker/Qt doubles. They do not establish pytest plugin/fixture equivalence,
coverage, Ruff/Pyright success, native Qt/DPI behavior or a Windows executable
build. No live connectivity or brokerage execution is claimed. Run the existing
run_all_tests.bat with the supported Windows/Python 3.14 toolchain and rebuild
before deploying an executable. The archive supplies reviewed source files,
not a prebuilt or broker-certified executable.
